## Krátká CVE/advisory rešerše za posledních 7 dní

Zaměřeno na reálně viditelný stack: Ubuntu 22.04/Jammy, Linux kernel 5.15, veřejné OpenSSH, lokální PostgreSQL 14, Python služby a čekající `iproute2`. Limit rešerše: 6 web dotazů; URL extrakce nebyla dostupná kvůli nastavení backendu, proto jsou níže použité výsledky z vyhledávání a lokální ověření verzí přes read-only příkazy.

- **PostgreSQL – CVE-2026-6474:** NVD výsledek a oficiální PostgreSQL advisory popisují únik částí paměti přes `timeofday()`; postižené jsou verze před 14.23. Host má `postgresql-14 14.23-0ubuntu0.22.04.1`, takže podle lokální verze je tato větev na opraveném minor release. Navíc PostgreSQL poslouchá jen lokálně.
- **PostgreSQL – CVE-2026-6476:** oficiální PostgreSQL advisory se týká `pg_createsubscriber` SQL injection a podle vyhledávání dopadá na větve 17/18 před 17.10/18.4. Tento host běží PostgreSQL 14, takže se nejeví relevantní.
- **Linux kernel – DirtyClone / CVE-2026-43503:** Ubuntu blog z 25. 6. 2026 uvádí dopad na více Ubuntu vydání a doporučení aktualizovat kernel a restartovat. Dnešní fakta ukazují kernel `5.15.0-185-generic`, `reboot-required=no` a `apt` nenabízí kernel update; z lokálních dat tedy není vidět čekající kernel oprava.
- **OpenSSH – CVE-2026-3497:** výsledek Snyk pro Ubuntu 22.04/OpenSSH popisuje GSSAPI zranitelnost a upozorňuje, že dopad se má posuzovat podle distribuční verze. Host má `openssh-server 1:8.9p1-3ubuntu0.15`, kandidát je stejný a `apt` nehlásí čekající OpenSSH update.
- **OpenSSH – CVE-2026-35385:** vyhledávání našlo záznam o problému v `scp` oprávněních u OpenSSH do 10.2. Bez potvrzení dopadu na Ubuntu Jammy balík a bez čekající OpenSSH aktualizace jde zatím jen o informativní položku.
- **iproute2:** lokálně čeká update na `5.15.0-1ubuntu2.2`, ale vyhledávání nenašlo jasný Ubuntu Security Notice/CVE pro tuto konkrétní Jammy aktualizaci; `apt-cache policy` ukazuje běžný `jammy-updates` phased rollout, ne `jammy-security`.

## Doporučené následné ověření bez změn systému

1. Doložit stav firewallu způsobem, který read-only audit zvládne bez interaktivního root přístupu.
2. Ověřit efektivní hodnotu SSH `PermitRootLogin` a záměrnost nedávných root přihlášení z veřejné IP.
3. Potvrdit, že veřejné Python služby na portech 8808 a 8765 jsou záměrně vystavené a mají autentizaci.
4. Doložit existenci obnovitelných záloh důležitých dat a konfigurací mimo samotné `/var/backups`.
5. V příštím běhu znovu zkontrolovat `iproute2`; pokud rollout doběhne a balík bude stále čekat, bude vhodné ho aktualizovat v běžném maintenance okně.
