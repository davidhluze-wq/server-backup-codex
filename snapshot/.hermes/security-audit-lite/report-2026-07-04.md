## Krátká CVE/advisory rešerše za posledních 7 dní

Zaměřeno na reálně viditelný stack: Ubuntu 22.04/Jammy, Linux kernel 5.15, veřejné OpenSSH, lokální PostgreSQL 14, Python služby a čekající `iproute2`. Limit rešerše: 6 web dotazů. Přímá extrakce URL není v tomto běhu dostupná (`DuckDuckGo` backend je pouze vyhledávací), proto jsou níže použité výsledky webového vyhledávání a lokální read-only ověření verzí.

- **OpenSSH – CVE-2026-35414 (NVD):** NVD výsledek popisuje problém v OpenSSH před 10.3 v méně běžném scénáři s `authorized_keys` `principals` a certifikační autoritou používající čárky. Host používá distribuční Jammy balík `openssh-server 1:8.9p1-3ubuntu0.15`; `apt-cache policy` neukazuje čekající OpenSSH update a kandidát je shodný s instalovanou verzí. Dopad je nutné posuzovat podle Ubuntu backportů, z dnešních lokálních dat nevyplývá neaplikovaná oprava.
- **Ubuntu Jammy security notices:** vyhledání nejnovějších Ubuntu Security Notices pro Jammy nenašlo v krátkém vzorku jednoznačnou novou položku pro OpenSSH, PostgreSQL 14 nebo `iproute2`, která by na tomto hostu čekala k instalaci. Lokální `apt` hlásí pouze `iproute2` z `jammy-updates`, nikoli samostatnou položku z `jammy-security`.
- **PostgreSQL 14:** krátké hledání NVD pro PostgreSQL vrátilo obecné výsledky, ale bez jasně relevantní nové chyby pro PostgreSQL 14. Host má `postgresql-14 14.23-0ubuntu0.22.04.1`, kandidát je stejný a služba poslouchá jen lokálně.
- **Linux kernel – Copy Fail / CVE-2026-31431:** Ubuntu blogový výsledek zmiňuje opravy pro kernelovou zranitelnost `Copy Fail`. Dnešní lokální stav: kernel `5.15.0-185-generic`, `reboot-required=no`, `apt` nenabízí kernel update; z dostupných dat tedy není vidět čekající kernel oprava.
- **iproute2:** čekající verze `5.15.0-1ubuntu2.2` je z `jammy-updates` s phased rollout 50 %. Webové hledání nenašlo jasný CVE/USN vztah pro tuto konkrétní Jammy aktualizaci; jde spíš o běžnou aktualizaci, ale stále je vhodné ji dořešit při údržbě.
- **Python/Python služby:** vyhledávání OSV pro obecné Python/FastAPI/uvicorn dotazy nevrátilo použitelný relevantní záznam. Fakta neobsahují konkrétní aplikační dependency lockfile, takže nelze spolehlivě mapovat CVE na balíčky těchto Python služeb.

## Doporučené následné ověření bez změn systému

1. Doložit stav firewallu způsobem, který read-only audit zvládne bez interaktivního root přístupu.
2. Ověřit efektivní hodnotu SSH `PermitRootLogin` a záměrnost nedávných root přihlášení z veřejné IP.
3. Potvrdit, že veřejné Python služby na portech 8808 a 8765 jsou záměrně vystavené a mají autentizaci.
4. Doložit existenci obnovitelných záloh důležitých dat a konfigurací mimo samotné `/var/backups`.
5. V příštím běhu znovu zkontrolovat `iproute2`; pokud phased rollout doběhne a balík bude stále čekat, zařadit aktualizaci do běžného maintenance okna.
